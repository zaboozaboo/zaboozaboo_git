# 원본 주사위 생산 + 전장 합류 비교판

`/reclaim/dice/`에서 실행한다. `/index.html` 원본, `/reclaim/` 전선판, `/reclaim/command/` 드래그 조작판은 그대로 보존한다. 저장 데이터를 읽거나 쓰지 않는다.

## 원본과의 연결

`../../js/data.js`와 `../../js/dice.js`를 수정 없이 직접 로드한다. `bridge.js`는 원본이 기대하는 상태, 정원 계산, 생성 함수만 새 전장에 연결한다.

- 첫 굴림 1.6초, 이후 기본 6초 간격.
- 모든 슬롯에 같은 눈금 동시 충전. 초기 로스터는 원본처럼 민병/궁수.
- 민병 4, 궁수 6 충전마다 실제 병사 1명 생성. 남은 충전 이월.
- 기본 정원 민병 20, 궁수 15. 가득 차면 최대 1명분만 충전 보관.
- 기본은 원본 자동 굴림. 체크를 끄면 첫 굴림 이후 준비된 주사위를 직접 누른다. 기다려도 여러 굴림을 무한 축적하지 않는다.

## 전장 표현

같은 민병 4 / 궁수 2로 시작해 생산 사용/중단을 비교한다. 적 3개 소대와 군단장은 처음부터 배치된다. 굴림 결과가 슬롯으로 날아가고, 생산된 병사는 고정 후방(y=1040)에서 출발해 걸어간다. 전선 가까이에 도착하면 합류 표시가 뜬다. 전선 인원, 행군 인원, 누적 생산을 별도로 표시한다. 병사는 실제 위치와 사거리로 공격하며 영웅 공격력에 병사 수를 곱하지 않는다.

전투는 조작판의 아트·이동·공격·예고 공격을 재사용하되 자동 진군과 생산 성장에 맞춰 별도 조정했다. 원본의 전투 밸런스 전체를 복사한 것은 아니다.

## 검증

`node territory/reclaim/dice/production.test.cjs`

원본 코드로 눈금/슬롯 충전, 비용 4/6, 정원 20/15, 정원 초과 충전 제한, 결원 보충, 수동 입력, 실제 행군, 생산 유무를 검사한다. 고정 난수 세 경우에 42.1–51.2초 승리, 생산 8–12명, 최대 병력 12–16명이었다. 같은 시작 병력으로 생산 없이 실행하면 패배했다. 승패를 모드에 따라 강제로 결정하지 않는다.
