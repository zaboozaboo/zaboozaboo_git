# Dungeon and growth runtime contract

## 장비 주사위 연출

장비 소환은 코랄 레드 3D 주사위로 표시하고 `Hammers`의 사용자 노출명은 주사위이며 아이콘도 같은 3D 주사위의 전체 형상·문양을 참조한 imagegen·Anima 그림을 사용한다. 저장 키·비용·8부위 확률·확정 지급 규칙은 유지한다. 6면은 무기·투구·갑옷·장갑·신발·기타이며 반지·목걸이·벨트는 반지 문양의 기타 면으로 묶는다. 주사위 회전은 저장이 완료된 결과를 표시하며 물리·표시 난수로 장비를 다시 판정하지 않는다. 자동 소환도 실제 생성된 결과 수만큼 주사위를 표시한다.

`ForgeDiceBuilder`가 편집 가능한 `Art/ForgeDice/EquipmentDie.fbx`를 읽어 모델 프리팹·머티리얼·전용 카메라를 조립하고 확정된 주사위 아이콘 원본을 복사한다. FBX 원본과 사용자 메시 수정은 재생성하지 않는다. `BattleSceneBuilder`는 HUD에 해당 프리팹을 연결한다. 기본 전투는 기존 URP 2D·Gamma를 유지하고 주사위 카메라만 별도의 Unlit 3D 렌더러와 RenderTexture를 사용한다. 주사위 전용 UI 레이어는 게임판·장비 그리드보다 앞, 소환·강화·자동 버튼과 최하단 메뉴보다 뒤에 두고 입력을 가로채지 않는다. HUD 비활성화 시 카메라·모델·RenderTexture를 해제한다.

주사위가 굴러가는 동안 크기는 고정하며 이동·회전만으로 위로 떠올랐다가 복귀한다. 주사위 자체의 확대·축소 보간은 사용하지 않는다. 결과 공개 시점에는 각 주사위와 그림자를 숨기고 같은 투영 위치에 확정 장비 아이콘과 해당 티어의 백판을 표시한다. 백판은 기존 `ui-slot`·`tier-N` 스타일과 `GameHud.SetTier`를 재사용하며 수동·자동 소환 모두 새 결과의 티어로 갱신한다. 보관 장비는 짧은 금빛·크기 강조로 나타나며 다음 굴리기까지 유지한다. 판매로 소유 목록에서 빠지면 아이콘과 백판을 즉시 숨기며 대기 전환에서 다시 표시하지 않는다. 자동 판매 결과도 520ms에 아이콘과 등급 백판을 공개하고, 300ms 동안 보여준 뒤 820ms에 숨겨 대기 주사위로 돌아간다. 자동 판매 아이콘은 잠깐 표시하는 동안 소유 목록에 없다는 이유로 조기 제거하지 않으며, 대기 전환·다음 굴림에서 다시 나타나지 않는다. 저장된 판매·보상 판정과 자동 굴림 주기는 유지한다. 획득 백판의 곡률·테두리는 일반 장비 슬롯의 공통 스타일을 따른다. UI 이미지에는 2.5배의 고정 촬영 여백을 둔다. 주사위와 접지 그림자는 내려다보기 52도·거리 30·기본 수직 시야각 12도를 쓰는 원근 카메라로 그린다. 카메라는 가상 바닥 중심을 바라보고 투영 중심 보정 0.2로 고정 촬영 영역을 위로 옮겨 던지기 여백을 확보하며, 수직 시야각은 개수별 촬영 범위로 계산한다(1개 12도). 게임판의 화면 아래까지 비대칭 투시를 연장하지 않고 주사위 영역 안에서 게임판에 가까운 수평면 각도와 완만한 원근을 유지한다. 카메라를 멀리 두어 높이 2인 단일 주사위의 윗면·바닥 간 확대 차이를 약 6%로 제한한다. 쟁반은 표시하지 않는다. 주사위마다 수평면에 부드러운 반투명 접지 그림자를 두고, 떠오르는 높이에 따라 넓고 옅어지게 한다. 회전된 외곽의 바닥 지지 높이를 계산해 바닥 관통을 방지한다. 단일 크기는 2, 다중 크기는 1.4로 유지하고 다중 배열의 촬영 여백을 최소화한다. 카메라 거리는 개수와 무관하게 30으로 고정한다. 결과 면은 윗면으로 유지하며, 결과를 표시할 때 각 주사위의 Y축 방향을 0~360도에서 한 번씩 무작위로 정한다. 표시 전용 난수는 보상 난수와 분리하고, 같은 던지기의 프레임 갱신·대기 복귀에서는 정해진 방향을 유지한다.

수동 굴림이 가능하고 결과 장비 표시가 없는 대기 상태에서는 주사위가 가끔 짧게 까딱이며 굴림을 유도한다. 재화 부족·실제 굴림·자동 소환·화면 또는 포커스 이탈 시 멈추며, 표시 전용 회전은 장비 결과·게임 난수·저장 상태를 바꾸지 않는다. 외곽선은 바깥 검정·안쪽 코랄색(`#FF7765`) 이중 테두리다.

주사위 사운드는 작은 탭 세 번과 착지에 맞춘 공개음으로 구성하며 수동·자동 모두 배치당 한 번 재생한다. 대기 어필에는 기존 탭을 더 작게 재사용하며 실제 소환의 공개음·햅틱은 재생하지 않는다. 강화 장비 햅틱은 결과 공개 시점에만 울리고 진동 설정·화면 표시·모바일 포커스를 확인한다. 타이밍·믹스 원천은 [효과음 파이프라인](../Tools/sfx/README.md#주사위-피드백)이다.

몸체는 300삼각형이며 같은 메시를 이용한 외곽선까지 총 600삼각형을 그린다. 여섯 문양은 생성한 단일 흑백 아틀라스를 사용하고, 아이보리 색과 얕은 음각의 가장자리 노멀·그림자는 재질에서 표현한다.


## 캐릭터 레벨·계급 승급

성공한 장비 분해마다 20 EXP를 로컬 저장한다. 단건·일괄·자동 분해가 같은 규칙을 쓰며 제작·장착·실패·재요청에는 경험치를 지급하지 않는다. `PlayerLevelInfo`의 920레벨 경험치·고정 능력치와 `MilitaryRankInfo`의 32계급 조건·보상을 사용한다. 계급 상한에서 초과 EXP를 보존하고 승급 후 새 상한까지 연속 레벨업한다. 마지막 계급의 최종 과제는 추가 레벨·능력치 없이 보상만 한 번 지급한다.

분해 보상은 저장 성공 후 `SaleRewardsGranted`·`AutoForgeSaleRewardsGranted`로 금화와 획득 EXP를 함께 전달한다. EXP 수량은 확정된 분해 개수로 계산하므로 레벨업으로 남은 경험치가 줄어도 획득량을 잃지 않는다. 메인 분해 연출은 기존 금화와 같은 일정·정리 경로에서 금화 개수의 약 80%에 해당하는 파란 XP 토큰을 함께 떨어뜨린다. 금화·XP 토큰 위에는 개별 수량 숫자를 표시하지 않으며, 골드 합계는 상단 재화 표시에서 확인한다. 토큰은 즉시 반영된 EXP의 시각 표현이며 별도 소비 아이템 재고를 만들지 않는다.

`ClaimMilitaryRankReward`는 레벨·캠페인·주사위 과제의 보상을 개별 수령하는 서버 경제 명령이다. 받기를 누르면 기존 경제 요청으로 조건·순번·미수령 여부를 검사하고 보상과 수령 비트를 원자 확정한다. 응답을 로컬 저장한 뒤 재화와 체크 표시를 즉시 갱신한다. 처리 중에는 중복 클릭을 막고 실패하면 미수령 상태를 유지하며, 응답 유실은 같은 작업 ID로 복구한다. 진행 중은 밝은 양피지 카드에 보상 아이콘·수량을 표시한다. 레벨 과제는 상한 전에는 현재 레벨/상한 레벨을, 상한 도달 후에는 수령 조건인 현재 EXP/필요 EXP를 표시한다. 마지막 계급은 추가 EXP 없이 상한 레벨 도달로 완료한다. 수령 가능한 카드는 밝은 배경·금빛 테두리로 강조하고 재화 앞쪽에는 RPG Project 1에서 가져온 작은 별 반짝임을 표시한다. 수령 후에는 어두운 양피지 바탕으로 바꾸고 금빛 강조를 걷되 보상 아이콘·수량은 유지하며, 별도 백판 없이 체크를 겹쳐 표시한다. 별도 받기 버튼 모양이나 상태 문구는 추가하지 않으며 수령 가능한 카드 전체를 눌러 수령한다. 누르는 동안 카드 전체에 눌림 연출을 적용하고 입력 취소 시 원상복귀한다. 보상 없는 조건도 달성 후 확인한다. `RankRewardClaims`의 레벨·캠페인·주사위 비트(1·2·4)가 모두 확정되면 `PromoteMilitaryRank`로 승급한다. 승급은 재화를 다시 지급하지 않고 수령 비트를 초기화한다. 마지막 계급의 최종 과제도 같은 수령·완료 흐름을 사용한다.

현행 StatLayers·반올림 후 레벨·계급 고정 정수를 더하고 장비 기반 동료 성장에 다시 곱하지 않는다. 계급군 마지막 과제 완료 시 시간 보상 상한을 900초 늘리며 13계급부터 칩 생산량을 분당 0.875개 추가한다. 승급 전 적립 시간에 새 생산 보너스를 소급하지 않는다.

레벨업 진행은 기존 5분 백업과 선행 재화 소비·아레나 요청에 결합한다. 승급은 로컬 저장 성공 직후 기존 `SyncCommitted` 경로로 백그라운드 동기화를 요청하며 화면·입력을 통신 완료까지 대기시키지 않는다. 과제 보상은 받기 요청의 응답 즉시 사용할 수 있다. 지갑·영수증 처리와 장애 복구는 [클라우드 계약](CloudBackend.md#레벨계급-비동기-정산), 상세 조건과 수치 원천은 [계급 설계](design/military-ranks/README.md)를 따른다. 기존 계정 레벨·경험치 변환, 과거 보상 소급 지급, 저장 삭제·초기화는 하지 않는다.

## Era identity

The ten existing zero-based age IDs map one-to-one to the following eras, in order. These names and themes are the game's presentation direction for equipment, characters, environments and future skill presentation. The groupings are stylized art direction, rather than strict historical period boundaries.

| Age ID | Korean display name | English display name | Theme and visual references |
|---|---|---|---|
| 0 | 석기 시대 | Stone Age | Stone axes, dinosaurs and mammoths. |
| 1 | 고대 시대 | Ancient Age | Egypt, Rome, Greece and Han-dynasty China. |
| 2 | 중세 시대 | Medieval Age | Drab barbarians, chainmail, longbows and crossbows. |
| 3 | 근세 시대 | Early Modern Age | Plate armor, Leonardo da Vinci and Columbus. |
| 4 | 근대 시대 | Late Modern Age | Muskets and Napoleon. |
| 5 | 산업 시대 | Industrial Age | British hats and trains. |
| 6 | 현대 | Modern Age | Aircraft, World War I and World War II. |
| 7 | 정보화 시대 | Information Age | Computers, AI, robots and cyberpunk. |
| 8 | 우주 시대 | Space Age | Space Marines (user reference: 스마), StarCraft and aliens. |
| 9 | 양자 시대 | Quantum Age | Visual concept not yet defined. |

Runtime display names are owned by `age_0` through `age_9` in [Interface_ko.csv](../Assets/_Project/Data/Interface_ko.csv) and [Interface_en.csv](../Assets/_Project/Data/Interface_en.csv), loaded by `LanguageManager`. Forge probability lists and automatic-forging age filters consume these shared keys. Numeric stage labels remain one-based.

The mapping preserves stored age IDs, equipment identities, stage ordering, unlock thresholds, drop probabilities and balance values. Source and extracted chart identifiers retain their original spelling for compatibility; historical reference documents are not the authority for the game's era presentation. See the [balance contract](BalanceContract.md). Era themes guide subsequent asset and skill work; existing artwork and skill effects are not automatically replaced by changing display names.

Equipment, pets and skills have independent acquisition/progression tracks. Each piece of content has its own fixed era identity; the player does not have one era that overrides all three tracks. Quantum equipment, a Modern pet and a Space skill may coexist. Each track uses its own forge/summon progression and existing chart rules. A content era is neither an automatic appearance upgrade nor an added player-era eligibility gate.

## Dungeon battles

| 던전 | 배경·적 테마 | 주 보상 |
|---|---|---|
| 고대의 신전 (`Hammer`) | 청동기 신전, 제사장·파라오·미라 계열 | 주사위(장비 소환 재화 `Hammers`), 기존 골드 부가 보상 유지 |
| 콜로세움 (`Pet`) | 검투 경기장과 기존 검투사 3종 | 훈련병 모집 재화 `Eggshells` |
| 병기 제작소 (`Skill`) | 중세·다빈치풍 공방, 트레뷰셰·기계 괴뢰·청동 및 금속 골렘 테마 | 스킬 티켓 |
| 해적의 섬 (`Potion`) | 해적 기지와 해산물 해적 테마 | 기술 연구용 빨간 물약 |

캐릭터 신규 제작은 제외한다. 신전은 기존 미라·파라오 의상, 콜로세움은 기존 검투사 의상을 재사용한다. 병기 제작소와 해적의 섬은 각각 기존 중세·대항해 캐릭터를 사용하며 전용 골렘·해산물 해적 외형은 미제작이다. 일반 캠페인 진행도와 무관하게 해당 시대의 외형·무기 판정을 함께 선택한다. 저장 ID·해금값·보상 수량·웨이브 수는 유지한다. 전용 배경·전경의 원천은 [던전 환경](art-source/dungeon-backgrounds/README.md)이다.

던전 해금은 현행 `FeatureUnlock`의 로컬 기획을 따른다. 보존된 APK PlayerSegments는 참고 원본이며 현재 해금표를 덮어쓰지 않는다. `HighestStage`는 다음 입장 가능한 스테이지로, 고대의 신전 21·콜로세움 31·병기 제작소 51·해적의 섬 71에서 열린다. 각각 20·30·50·70스테이지를 클리어한 뒤 이용하며, 용병·스킬·기술 연구는 해당 재료 던전과 동시에 열린다. 이전 스테이지를 재도전해도 해금은 유지한다. 메뉴와 개별 카드는 잠금 조건을 표시하고 Application은 같은 조건을 저장·입장 전에 검사한다. 기존 던전 레벨·열쇠는 보존하지만 진행 조건을 우회하지 않는다.

성장 메뉴는 용병 31·스킬 51·기술 71스테이지에 순차적으로 열린다. 성장 버튼은 용병 해금을 따르고, 기억한 성장 탭이 잠겨 있으면 용병 탭으로 진입하며 탭·빈 스킬 슬롯 진입도 같은 잠금 조건을 사용한다. Replaying earlier stages does not relock menus; existing owned skills, pets and research are retained. Application skill, pet and research commands enforce their menu requirements before saving. 시간 보상은 5스테이지 클리어 뒤(최고 진행도 6) 열린다; 적립은 해금 여부와 관계없이 첫 서버 로그인 경제 조회부터 시작한다. 해금 별도 통신은 없고, 기존 로컬 누적은 가져오지 않는다. 수령·잔여량 확정은 [서버 원장](CloudBackend.md#시간-보상-서버-원장), 상한·지급 비율은 [Offline 계약](BalanceContract.md)을 따른다. The rest popup places the gold rewarded-ad ×2 claim on the left and the blue ordinary claim on the right. `030_Dungeons` supplies four independent sequences of 400 levels. Display stages are source levels plus one. Positive Wave1/2/3 values are enemy counts; non-positive entries are disabled waves. Hammer Thief omits wave and enemy identities; the pinned public BattleSimulator uses one enemy with id 0 for that library. A negative second enemy identity means the first enemy type is repeated. Dungeon health and damage are absolute values and do not receive main-stage calibration or ranged scaling.

Unlocked dungeon cards open a detail popup before entry. The popup shows the current challenge stage, research-adjusted challenge and sweep reward previews, remaining keys and reset rules; closing it returns to the same list position. Details remain accessible with zero keys, while actions are disabled. Challenge submits server `EnterDungeon`; the server checks unlock, progression and keys without spending. Sweep uses the highest cleared level of that dungeon, consumes one key, and grants that level's research-adjusted rewards in one saved transaction without entering battle or advancing progress. Sweep remains unavailable until the first clear. At the 400th level, an optional saved completion flag distinguishes a cleared final level from an uncleared one; older saves without that flag conservatively sweep displayed stage 399 at most. Failed saves spend no key and grant no rewards. The UI does not offer difficulty selection.

Entry uses the existing battle lane. Main-stage progress and kill rewards are suspended during the challenge. Server `ExitDungeon` accepts the client victory/defeat result. Victory atomically consumes one current-day key, grants chart rewards and advances only that dungeon; defeat and exit spend nothing. The last level remains replayable. Termination leaves the run uncharged, and a new start abandons it. Lost responses retain the operation ID for receipt recovery. Server-owned balances and local reward deltas follow the [economy contract](CloudBackend.md#서버-재화닉네임). Explicitly isolated local sessions retain local settlement for offline tests.

던전·아레나·친선전은 시작 요청 순간부터 메인 전장으로 돌아오는 전환이 끝날 때까지 메인 전투와 자동 주사위 생성·소모를 정지한다. 던전 전투 자체는 계속 진행하며, 메인 전투의 체력·적·공격·스킬 및 전환 상태는 메모리에 보관했다가 복원한다. 자동 굴림 실행 여부와 누적 대기시간도 유지하며 정지 시간을 복귀 후 몰아서 처리하지 않는다. 복귀 전환이 끝나면 결과창·리그·채팅 UI가 열려 있어도 재개한다. 입장 실패·취소로 전투가 시작되지 않으면 정지를 해제한다. 던전은 기존 자동 보상 연출과 메인 복귀 흐름을 유지한다. 앱 재시작 후 전투 중간 상태 복원은 이 계약에 포함하지 않는다.

아레나·친선전과 친선전 다시보기는 입장 시 같은 검은 전환을 사용한다. 서버 응답 대기와 0.4초 페이드아웃을 함께 수행하고, 검은 화면 아래 전투 화면을 준비한 뒤 두 프레임을 기다리고 0.5초 동안 밝아진다. 입장 전환이 끝날 때까지 전투 시뮬레이션을 진행하지 않으며, 실패·취소 시 전환 화면과 요청 중 상태를 해제한다.

Rewards are floor(base + sourceLevel * increase), multiplied by matching completed research before rounding. The pet reward table includes floating-point noise around increments of 0.65, so rounding tolerates 1e-7. Initial rewards: Hammer Thief 60 hammers and 4,000 gold; Ghost Village 200 skill tickets; Invasion 200 eggshells; Zombie Rush 100 tech potions. At 00:00 UTC (09:00 KST), each dungeon refills to at least two keys: `max(currentKeys, 2)`. Higher balances, including purchased extras, are retained without adding a daily allowance. Free and purchased keys share one balance, matching the [APK daily-refill evidence](research/forge-master/evidence/daily-deals-arm64.txt).

Successful dungeon settlement publishes a transient receipt containing the actual currency deltas only after saving. The HUD shows exact received quantities in a short central popup, then sends the currency icons to their HUD destinations: gold and gems to the top counters, and dungeon materials to the bottom-center Growth button. Receipts queue independently of page refreshes and are cleared when the HUD unbinds. Failed saves, defeats and exits publish no reward receipt. This presentation does not add currencies to the reward tables.

### Combat and progression

All 18 source identities have stable runtime aliases; the original twelve save IDs remain valid. Five timed buffs are Meat, Morale, Berserk, Buff and HigherMorale. Buff health increases maximum health and heals that amount; expiration removes the maximum-health bonus and clamps current health. Drone performs periodic single-target attacks. Other skills use explicit multi-hit and area/single-target mechanics. Multi-hit single-target attacks select a living target each pulse. 공격력·체력은 기본·장비 기준값과 등급별 기여율에서 계산하며 `019_Skills`·`020_Skill_Passive`는 원본 1레벨 대비 성장비를 제공한다. 자세한 수치·연구 적용 순서는 [비장비 성장 계약](BalanceContract.md#비장비-성장-기여)을 따른다. Upgrades consume `021_Skill_Upgrades` shards. All owned passives contribute even when the skill is not equipped. Three distinct skills can be equipped. 용병 슬롯은 31·46·61·76, 스킬 슬롯은 51·66·86스테이지에서 열린다. Slot requirements apply to manual equip, automatic equip, quick equip and battle profiles. Session resume clears saved assignments in locked skill and pet slots in the existing atomic resume save. Owned skills, skill levels, shards and pets are retained; unlocked assignments remain unchanged. A failed save aborts resume without overwriting the stored assignments. Unlocking a slot does not restore a cleared assignment automatically.

The pinned public simulator’s [constants.ts](https://github.com/1vcian/fm/blob/08efb9c6ea586c2882bb58858b1c5ca7da605009/src/utils/constants.ts) and [BattleEngine.ts](https://github.com/1vcian/fm/blob/08efb9c6ea586c2882bb58858b1c5ca7da605009/src/utils/BattleEngine.ts) provide operational timing/buff behavior; this is analytical source evidence, not a recovered native implementation. Stampede·StrafeRun·Drone의 타격 시간은 이 원천을 따르되 현행 발동 총량은 실제 반복 타격 수에 나누어 배분한다. Lightning has contradictory numeric/name counts (5 versus fractional 3.5) in that source; this runtime preserves five integer hits and the canonical total damage. Waves are parts of one stage: current HP, skill cooldowns, active buffs and pending field effects carry across wave boundaries. 스킬 지속시간·발동 타이머·쿨다운은 같은 스테이지의 웨이브 준비·등장 중에도 계속 흐른다. 이미 발동한 스킬은 적이 없는 동안 타격을 소모하며, 다음 웨이브 적이 생성된 뒤 남아 있는 타격만 그 적에게 적용한다. 빈 구간의 타격을 보류하거나 웨이브 경계에서 갱신하지 않는다. 대상 없는 표시 이벤트로 기존 월드 연출도 계속 진행한다. 새 시전과 기본 공격은 착지 이후에만 시작한다. Health changes only through actual damage, recovery, buffs and their expiry/clamping. A new stage or restart constructs a fresh battle with full profile HP and cleared skill cooldown/effect state.

Skill arithmetic follows the [APK 2.9.0 combat restoration](research/forge-master/README.md#combat-5): Arrows/CannonBarrage divide damage by three, Shuriken/Meteorite/Lightning by five, Shout by eight and RainOfArrows by fifteen. Thorns, Stampede, StrafeRun and Drone use the full source damage per hit. Area pulses use strict greater-than boundaries, one regular pulse per frame and a separate final pulse where specified. Drone uses a 10/60-second attack interval. Skill hits use target defenses but do not inherit normal-attack critical or life-steal stats. Active duration precedes cooldown without carrying an overrun into the next timer. [CombatFormulas.md](CombatFormulas.md) records the implemented formulas and remaining spatial/numeric limitations.

Skills summon between 5 and 100 pulls per action under the local product rule, using as many pulls as the current tickets can afford within that range. Commands outside that range are rejected without spending tickets or changing state. With insufficient tickets for five pulls, the button shows the five-pull ticket cost and is disabled. 스킬 소환 레벨별 비용·진행·시대 확률은 `SkillSummonInfo`가 소유한다. `018_Summon_Rates`는 용병·탈것에만 사용하며 보존된 Handoff 원본의 과거 스킬 확률은 런타임에서 읽지 않는다. Research bonus eggs retain the paid egg’s rarity, do not advance progress, and only occupy space left after reserving all remaining paid eggs; a full collection suppresses bonuses as in single summons. Invalid counts, insufficient funds, insufficient space for paid eggs, and failed saves leave the whole batch unchanged. Each pull uses the then-current level's probability, normalized within the documented floating tolerance, and advances saved summon progress; later pulls in a batch use the resulting level. 스킬 소환은 single cost × count × 잔여 `SkillSummonCost` 배율을 계산한 뒤 [경제 수치 정리 규칙](BalanceContract.md#추가-경제-수치-개편)으로 반올림한 총액을 한 번 차감한다. 별도 묶음 할인은 없다. The information popup reads every displayed percentage and requirement directly from the active level row. Successful skill summons retain ordered result IDs only as transient presentation state after the save commits; batches above five are grouped by skill in the result display. The result overlay fades in and reveals its icons in order. 스킬 소환 결과는 공통 테두리와 순차 등장 연출을 사용하며 희귀도 강조는 하지 않는다. 훈련생·탈것 소환 결과에는 등급 연출을 사용한다. 결과 연출 상태는 저장하지 않는다. The fixed 75/250 skill choices and 15/50 egg choices are not exposed as separate buttons. 자동 장착은 현재 연구·승급·장비 옵션·공격 주기·용병 수와 실제 반복 타격 수를 반영한 결정적 기여 점수를 사용한다. 광역 대상 수·조합 시너지까지 예측하는 최적 편성 판정은 아니다.

스킬 장착·빠른 장착·소환 후 빈 슬롯 자동 장착은 같은 저장에서 `AutoSpell`을 켠다. 마지막 스킬 해제·승천·서버 보유 스킬 갱신으로 모든 슬롯이 비면 끈다. 장착된 스킬이 있는 동안 Auto 버튼으로 수동 전환할 수 있으며, 다음 장착 시 다시 켜진다. 소환 영수증 재적용처럼 실제 장착이 없는 갱신은 수동 선택을 유지한다. 저장 실패 시 장착과 Auto 상태 모두 이전 값을 유지한다.

The skill page and its detail/ascension dialogs omit generic save-success and storage-failure notices. Storage failures are logged to the Unity Console; failed commands still preserve prior state, and other actionable command errors remain visible.

Skill names and artwork follow `SourceSkillKey`; existing save-facing `SpellId` values remain stable. The detail modal formats per-hit damage, active health/duration, cooldown and owned passives from `SpellProfile.ForSkill` and `GrowthRules.SkillPassive`, including research and ascension. Pulse skills describe damage per pulse rather than claiming an exact total from rounded frame intervals. `UnequipSpell`은 슬롯 해제와 마지막 슬롯 해제 시 Auto 끄기를 저장하며 레벨·조각·패시브는 유지한다.

### Skill ascension

Skill ascension unlocks at skill summon level 100 and has three stages. `SkillAscensionInfo` is a reproducible projection of the Skills entry in the extracted APK 2.9.0 `AscensionConfigsLibrary`; its costs are null. `Tools/import_handoff.py` produces the projection without modifying canonical handoff tables. Source contributions 49, 2499 and 124999 apply as a separate `1 + contribution` multiplier: cumulative ×50, ×2,500 and ×125,000. Only the current stage applies; stages are not added or multiplied together. Active Damage/Health and owned passive Damage/Health use their respective columns. Cooldowns, durations, equipment and pet stats are unaffected.

The `AscendSkills` command clears owned skills, duplicate shards and all four equipped slots; it resets summon level/progress to 1/0 and increments the shared skill ascension stage. Skill tickets, other currencies, auto-cast preference, research, dungeon keys/progress, forge state and main-stage progress are retained. This reset/preservation contract is corroborated by the [community ascension description](https://forge-master.fandom.com/wiki/Ascension); it is an explicit local contract, not a claim of recovered native reset code. The unlock and multipliers are extracted configuration evidence. Ascension does not implement the separately force-locked shared ascension-star currency bonus, new skill artwork, or other ascension pillars.

The entire change saves before acknowledgement. A failed save leaves collection, summon progress, ascension stage and battle effects intact. Successful ascension refreshes the battle profile without restarting the stage, removes active skill effects and clears skill timers and pending cast inputs. Fresh summons use the reset probability row and receive the new stat multiplier. Optional schema-3 `gr.as` stores the stage; absent keys default to zero without changing existing skills. Invalid stage values are rejected on domain validation.

## Mercenaries (pet-compatible progression)

적 로스터 전체 100종을 시대별 10종씩 용병으로 모집한다. 용병은 시대에 대응하는 `Tier1`~`Tier10`, 훈련병은 일반·희귀·영웅·전설·궁극 5티어다. 훈련병마다 인접한 두 시대의 용병 20종에서 균등 추첨한다(일반 1~2티어, 희귀 3~4티어, 영웅 5~6티어, 전설 7~8티어, 궁극 9~10티어). 기존 신화 훈련병과 소환 확률은 궁극으로 합치며, 진행 중 종료 시각은 유지한다. 새 훈련 시간은 각각 5·20·40·80·160분이며 궁극에는 기존 궁극·신화 시간 단축 연구가 모두 적용된다. 기존 용병 저장 쌍은 [명시적 이관표](art-source/character-sets/mercenary-retired-species.json)의 `identities`로 새 티어·종에 연결하고 ID·레벨·경험치·잠금·편성을 보존한다. 기존 40종 외형 인덱스·키와 유형은 유지하고 새 60종을 추가한다. 10티어 성장 차트는 기존 6단계의 양 끝을 유지해 가장 가까운 단계로 배분하며 보유 효과의 티어 계수는 0~5 구간에 균등 배분한다. 편성은 4칸이다. 기존 3칸 저장은 ID·순서를 보존하고 빈 네 번째 칸을 추가해 읽는다. With the cloud session bound, `SummonEgg`, `StartHatch` and `CollectHatch` use the existing economy command API. The server owns pending eggs, training slots/end times and claimed identities; it rolls rarity on summon and species on collection. `StartHatch` assigns a free slot and server end time. `CollectHatch` checks that time and consumes the egg once, returning the awarded mercenary. The client only displays the countdown and waits for a successful receipt before showing a result; no request is sent just because the timer ends. Owned eggs, incubator slot/time, pets and four equipped IDs persist. There are two initial incubators, purchasable third/fourth slots at the source 200/400-gem costs, and rarity timers from `015_Eggs` divided by `GameplayConfig.HatchDurationDivisor=6` (Common 5 minutes, Rare 20 minutes). Existing quoted end times are retained. Completed eggs require collection. Summoning and collecting are transactional; failing to save leaves eggs, currency and pets unchanged.

장착 용병의 보너스는 [비장비 성장 계약](BalanceContract.md#비장비-성장-기여)의 기준 능력치 기여율, `014_Pet_Upgrades`의 레벨 성장비, `013_Pet_Balance`의 유형 배율과 완료한 용병 연구로 계산한다. Un-equipped pets add nothing. 이 능력치 보너스와 별개로 편성 용병은 공격 시점의 플레이어 공격력(공격 버프 포함)을 3으로 나눈 뒤 소수점을 버리고 [전투 수치 정수화](BalanceContract.md#전투-수치-조정)한 공격력으로 독립 전투한다. 3 미만은 0이다. 용병 최대 체력은 `CombatBalance.Third(플레이어 최대 체력)`이고 편성 시 이 체력으로 시작한다. 용병은 개별 현재 체력과 전투 ID를 가지며 기본 공격의 공격 속도·치명타·흡혈·회피·방어·반사 옵션은 소유자의 것을 사용한다. 흡혈은 해당 용병을 회복하고 반사는 해당 용병에게 피해를 준다. 기본 공격은 사거리 안에서 상대 팀의 생존 전투원 중 가장 가까운 대상을 고른다. 단일 스킬은 상대 플레이어가 사망하면 생존 용병을 대상으로 삼고, 범위 스킬은 상대 팀의 생존 전투원 전체에 적용한다. 용병은 자기 무기의 기본 공격만 수행하며 별도 스킬 슬롯은 없다. 아레나는 양쪽 플레이어와 용병에 같은 규칙을 적용한다. 용병 사망은 이동·칸 점유·공격을 중단하고 처치 수·보상을 늘리지 않는다. 현재 체력과 사망은 용병 보유 ID별로 같은 전투의 편성 슬롯 이동·장착 해제/재장착·웨이브 사이에 유지하며 새 전투에서 초기화한다. 능력치 갱신은 현재 체력을 새 최대 체력으로 제한하며 사망을 되돌리지 않는다. 근접 기본 공격은 접촉 때, 원거리 기본 공격은 자기 위치에서 발사한 투사체 도착 때 피해를 판정한다. 용병 해제는 해당 용병이 발사했거나 해당 용병을 향한 미완료 기본 공격·투사체를 취소한다. 이미 발사한 투사체는 발사자의 사망 후에도 도착할 수 있다. 정수 처리 전 명목 공격력 합계는 현재 최대 4명에서 7/3배이며 실제 초당 피해는 각자의 무기·거리·공격 주기에 따라 달라진다. 수집 화면과 전투 용병 40종은 제작된 시대별 머리·투구·몸통·팔·손·무기를 [용병 파츠 외형](art-source/character-sets/README.md#용병-파츠-외형) 매핑으로 조립하며, 공통 본 리그의 대기·이동 애니메이션을 표시한다. Each source `(Rarity, Species)` pair has its own stable appearance index through `PetAppearance`, including species numbers shared across rarities; 시대 식별자·능력치·편성 4슬롯·보유 ID는 보존한다. Anonymous hooded recruits, training slots and training timers are the localized presentation of the existing egg/hatch commands. The popup uses a training-camp backdrop and straw dummies; recruits share one silhouette with rarity-colored clothing, use the original whole-body wooden-sword poses with a brief guard pose between windup and contact, and lower the sword or salute with gold sparkles when ready to collect. Dummy upper bodies recoil around fixed support posts; short straw-colored impact lines mark contact. The battle simulation owns mercenary cells, adjacent hop timing and formation returns. Mercenaries reserve both hop endpoints until landing, and player/enemy pathfinding respects those reservations. Presentation은 불변 `MercenaryFrame`으로 위치·이동을 표시하며, 용병은 플레이어·적과 같은 `UnitActor` 프리팹 스케일과 보드 원근 비율을 사용하며 0.84칸 바닥 판을 유지한다. 용병은 자기 무기의 근접·원거리 구분, 사거리, 공격 주기와 투사체 설정으로 독립 전투한다. 플레이어와 같은 액터 경로로 이동·공격·피격·사망을 표시하고, 최단 접근 경로가 여러 개이면 플레이어를 중앙에 두고 슬롯 순서대로 아래 1칸·위 1칸·아래 2칸·위 2칸의 편성 위치에 가까운 칸을 우선한다. 비탑승 시작 편성은 플레이어가 근접이면 용병을 한 열 뒤에, 원거리이면 한 열 앞에 두며 위아래 슬롯 순서는 유지한다. 3·4번은 위아래 2칸을 유지하되 1·2번보다 한 열 뒤로 물려 대각선으로 배치한다. 보드 뒤쪽 끝에서는 가장자리 열로 제한한다. 무기 유형 변경 때 편성을 갱신한다. 탑승 시에는 2×2 점유를 유지하고 용병 전원을 소유자 뒤에 두며 1·2번은 인접 열, 3·4번은 그 뒤 열에 둔다. 탑승·하차 때 편성을 다시 배치하되 현재 체력·사망 상태는 유지한다. 전투 중에는 사거리에 따라 이동한다. `PetAppearance`의 무기 설정을 외형 builder와 클라이언트·아레나 서버 판정이 함께 소비한다. 플레이어가 죽어도 살아 있는 용병은 전투를 계속하며, 아레나는 양쪽 팀의 전투원 전체가 사망했는지로 승패를 확정하고 시간 제한에서는 팀 전체 체력 비율을 비교한다. 수집·상세·소환 결과·편성·프로필도 같은 파츠 외형을 사용하며 이전 정지 이미지는 표시 경로에서 제외한다.

용병 상세 화면은 잠금과 장착·장착 해제를 제공하며, 보유 목록에 잠금 배지를 표시한다. 잠금은 대상의 장착·해제·업그레이드를 막지 않는다. `UnequipPet`은 선택한 용병의 편성 슬롯만 비우고 보유 정보·레벨·경험치·잠금과 다른 슬롯을 유지한다. 편성 변경은 저장 성공 후 전투에 반영하며 저장 실패 시 기존 편성과 revision을 유지한다. `gr.p[].lk`는 이전 저장에서 누락되면 false이며, 잠금 명령도 저장 성공 후 상태를 발행한다. 용병 잠금·편성과 스킬 편성 변경은 로컬에 즉시 저장하며 팝업 닫기·화면 이동으로 서버 요청을 만들지 않는다. 연결 중에는 기존 5분 주기 백업에서 변경된 저장만 전송하고, 앱 백그라운드 전환 시에도 동기화한다. 아레나 입장·상대 조회는 백업을 요청하지 않는다. 경기 시작은 마지막 서버 반영 전투 입력과 달라진 경우에만 `arenaInput`을 같은 시작 요청에 포함하고, 변경이 없으면 이를 생략한다. 서버는 보유·슬롯을 검증하고 해당 입력으로 경기를 확정한다. 응답 유실 시 같은 요청 ID와 동결한 입력으로 재시도하며 성공 응답 뒤 반영 기록을 갱신한다. 동기화 실패 시 로컬 저장과 기존 재시도·복구 경로를 유지한다.

업그레이드 재료에는 훈련 대기 중인 훈련생도 포함하며, 훈련 슬롯에 배치된 훈련생은 완료 시각이 지나도 수령 전까지 제외한다. 훈련생 경험치는 `015_Eggs.MaterialExperience`의 등급별 고정값이다. 용병과 훈련생을 합쳐 최대 5명까지 선택하며, 서버는 성장·두 종류 재료의 삭제·남은 훈련생 목록을 담은 영수증을 원자 저장한다. 업그레이드는 클라이언트에서 재료 1~5명과 예상 레벨·공격력·체력·잔여 경험치를 표시하고, 확정 버튼에서 `MergePet`을 서버 경제 명령으로 보낸다. 서버는 보유 원장의 대상·재료 ID, 중복·자기 자신·개수·최대 레벨을 검증하고 `014_Pet_Upgrades`의 재료별 `CumulativeXP`와 잔여 경험치를 합산한다. 다음 행의 `Experience`가 다음 레벨 비용이며 최대 100레벨 초과 경험치는 보존한다. 대상의 ID·희귀도·종류를 유지하고 성장과 재료 삭제·영수증을 원자 저장하므로 소환 보유 한도도 함께 줄어든다. 클라이언트는 영수증 복구 순번을 맞춘 뒤 응답의 서버 용병 전체 목록을 로컬 저장하고 전투 능력치를 갱신하며, 서버 미연결 시 로컬 합성으로 대체하지 않는다. 잠금·편성은 로컬 보호 상태로 재료 선택·명령 제출에서 검사하고 서버에 동기화하지 않는다. 목록 갱신은 같은 ID의 로컬 잠금·편성을 보존하고 서버에서 사라진 ID만 정리한다. 잠금·편성 변경은 로컬에 즉시 반영하고 기존 비동기 백업으로 보존한다. 중복 클릭을 막고 실패 시 선택을 유지하며, 불확실한 응답이나 로컬 저장 실패는 동일 작업 ID의 영수증으로 복구한다. 개발 중 로컬 합성 데이터의 서버 이전은 제공하지 않는다. `014_Pet_Upgrades`의 1,000개 SecondaryStats 필드는 모두 비어 있으며 용병 부가 옵션은 생성하지 않는다.

`QuickEquipPets`는 보유 용병의 현재 `PetStats` 공격력 × 8 + 체력 점수 내림차순으로 해금된 편성 슬롯을 채운다. 동점은 ID의 ordinal 오름차순으로 고정하며 잠긴 용병도 장착할 수 있다. 남는 슬롯은 비우고 보유 정보·성장·잠금은 유지한다. 메뉴 미해금·빈 보유 목록은 변경하지 않는다. 기존 로컬 장착과 동일하게 저장 성공 후 편성·전투·첫 장착 가이드를 반영하며, 즉시 서버 요청을 추가하지 않는다. 용병 팝업 하단 소환 영역 위의 빠른 장착 버튼으로 실행하며 보유 용병이 없으면 비활성화한다. 이 점수는 능력치 기여도 기준이며 무기 사거리·공격 주기·조합 시너지의 최적 편성을 계산하지 않는다.

### 용병 시대와 훈련생 등급의 구분

훈련생의 5개 등급은 소환 확률·훈련 시간·배출 시대 범위에만 사용한다. 훈련을 마친 용병은 시대와 레벨로 성장하며 이름에 시대를 표시한다. 수집·상세·합성·훈련 결과의 희귀도 색상과 희귀 획득 연출은 사용하지 않는다. 저장과 차트의 `Rarity`/`PetId.Rarity` 필드는 기존 개체 보존을 위해 유지하지만 `Tier1`~`Tier10`은 원시~양자 시대를 뜻한다. 전투 기여율은 `PetBonusBasePermille=50`부터 `PetBonusMaximumPermille=175`까지 시대별 선형 보간하며, 이전 수치와 성장 곡선은 보존한다.

## Mounts

`GrowthData.ManaCrystals` stores the mount summon currency. The original chart identifier is `ClockWinders`; the JSON save key is `gr.mc`. Saves written before the rename store the same currency as `gr.cw`; it is read as ManaCrystals and the next save writes only `gr.mc`.

`016_Mounts`는 12종을 등급별 전용 외형으로 분류한다. Common은 원시 티라노(0)·안장 달린 말(1)·맘모스(10), Rare는 전투 코끼리(2)·기사의 갑옷말(3)·로마 체리엇(11), Epic은 미니 범선(4)·미니 석탄기차(5), Legendary는 티거 I 전차(6)·탑승형 비행 드론(7), Ultimate는 로봇 티라노(8), Mythic은 양자 드래곤(9)이다. `Species`는 등급 내 순번이 아니라 `MountVisualSet.Appearances`와 [탈것 매니페스트](art-source/mounts-era-v1/runtime-manifest.json)의 전역 외형 인덱스다. 소환한 등급 안에서만 종을 균등 추첨한다. 기존 보유 개체의 등급·ID·레벨·경험치·잠금·장착 ID는 보존한다. 로그인 시 현재 등급에 없는 기존 외형(0~11)은 해당 등급의 종 번호 오름차순 목록에서 `이전 Species % 종 수`로 정규화하고 기존 Resume 저장에 포함한다. 이미 유효한 조합은 유지하며 범위 밖 외형과 알 수 없는 등급은 거절한다. 저장 실패 시 원본을 보존하고 초기화를 중단한다. 추가 외형 에셋은 별도로 보존하며 아직 `016_Mounts` 소환 대상에 편입하지 않았다. Summons use the current mount level's normalized rarity probabilities and `SingleCostAmount` in `018_Summon_Rates` (50 ManaCrystals). Species are selected uniformly within the rolled rarity. Every generated mount, including a research bonus, advances mount summon progress independently of skills and eggs, capped at level 100. Each result has a separate stable owned identity, including duplicates. The local inventory limit is 500. Summon and equip commands save atomically before publishing changes; failed writes spend nothing and leave equipment unchanged.

`SummonMount`는 탈것 메뉴 해금 후 별도 일괄 해금 없이 1~50회를 받는다. 버튼 하나가 보유 재화와 남은 보관 공간으로 가능한 최대 유료 횟수를 자동 선택하며, 소환할 수 없으면 1회 비용을 표시하고 비활성화한다. 기존 `PossibleSummonCount`·`BulkUnlockThreshold` 원본 차트와 저장된 `MountBulkUnlocked` 값은 보존하지만 소환 횟수·권한 판정에는 사용하지 않는다. `UnlockMountBulk` 명령은 사용하지 않는다. 일괄 비용은 기본 단일 비용 × 유료 횟수 × 할인 후 배율에 공통 경제 반올림을 한 번 적용하며 별도 일괄 할인은 없다. 각 유료 결과는 등급·외형 추첨 전에 추가 획득을 추첨하고, 보너스 결과는 유료 결과 뒤에 생성한다. 모든 유료 결과의 공간을 먼저 확보하며 남는 공간을 넘는 보너스만 생략한다. 생성된 결과마다 당시 소환 레벨의 확률을 사용하고 진행도를 올린다. 범위 밖 횟수·재화 부족·유료 결과의 공간 부족·저장 실패는 이전 목록·재화·진행도를 보존한다. 클라우드 연결 시 서버 경제 명령 한 번으로 묶음을 정산한다. 탈것 소환은 스킬·용병과 같은 준비·결과 overlay를 사용한다. 서버 응답 대기 중 소환 재화 아이콘과 링을 움직이고 입력을 막으며, 성공 후 새로 확정된 각 탈것을 등급색 원형 카드로 순차 공개한다. 전설 이상은 공통 강조·플래시·효과음을 사용한다. 결과 화면 터치로 닫고 실패·HUD 해제에는 준비 연출을 정리하며 미확정 보상을 표시하지 않는다.

One owned mount may be equipped; an empty equipment ID unequips it. Only the equipped mount adds `017_Mount_Upgrades` damage and health before player-wide stat layers. Stored levels 1–100 map to source levels 0–99. Changing equipment refreshes the current battle profile without healing. All secondary-stat fields are empty; non-empty secondary data fails catalog validation until a consumer is defined.

메인 탈것 팝업은 보유 목록과 소환 재화·1~50회 자동 소환·소환 레벨 진행을 표시한다. 정보 버튼은 스킬·용병과 같은 별도 소환 확률 팝업을 열며, 레벨 1~100 탐색·등급별 확률·현재 레벨 진행도를 제공하고 닫으면 탈것 목록으로 돌아간다. 카드에는 등급 배경, 외형과 장착 표시가 있으며 아이콘 아래에 이름, 그 아래에 레벨을 표시한다. 카드를 누르면 상세창이 열리고 장착/장착 해제 버튼으로 상태를 바꾼다. `EquipMount`는 보유 ID의 능력치 장착과 해당 `Species`의 탑승 외형을 하나의 저장 트랜잭션으로 반영한다. 팝업 아이콘은 `BattleSceneBuilder.PrepareMountArt`가 원본 알파 가중 면적을 계산해 등록된 외형의 그림 면적을 같게 맞춘 `MountAppearance.IconSize`로 중앙 배치한다. 최대 변은 130 UI 단위이며 원본 비율·픽셀과 전투 크기는 보존한다. 무료 12종 외형 선택 UI는 사용하지 않는다. 전투의 `GrowthData.RidingMount`와 저장 key `gr.ride`는 기존 외형 소비 경로를 유지하며, Editor/Development 전용 `RideMount` 명령은 외형 검증에 남긴다. 로그인 시 저장된 자유 선택 외형은 버리고 `EquippedMount`가 가리키는 보유 탈것의 `Species`로 탑승 상태를 재구성한다. 장착 ID가 없으면 미탑승으로 시작하며 기존 Resume 저장 경로로 반영한다. 별도 마이그레이션·버전 분기는 두지 않는다. 저장 실패 시 기존 파일을 보존하고 초기화를 중단한다. 원본·재단·좌석 기록은 [탈것 매니페스트](art-source/mounts-era-v1/runtime-manifest.json)에 보존한다. 추가 외형 4종(바퀴 달린 목마·무쇠 로봇꽃게·공허 비행선·고대 이집트 전차)은 인덱스 12~15에 보존한다. 이들의 Sprite 피봇은 안장·탑승칸 기준이며 `SpriteOffsetY`로 기존 바닥 높이를 유지한다. 꽃게는 정면을 보며 좌우로 이동하는 옆걸음 구도다. 소환 가능 여부는 외형 수가 아니라 `016_Mounts` 차트가 결정한다.

탑승한 플레이어는 `CombatProfile.FootprintSize=2`인 대형 유닛이다. `UnitFrame.Cell`을 좌하단 기준으로 열·행 각각 두 칸을 점유하며, 투사체와 점유 표시는 네 칸의 중심을 사용하고, 탈것 그림의 발밑 피봇은 아래쪽 타일 행 중앙에 맞춘다. 그림은 기존 크기를 유지하며 점유 크기에 맞춰 축소하지 않는다. 하차하면 1×1로 돌아간다. 경로 탐색·배치·보드 경계·길막은 전체 사각 영역을 검사하고, 이동 중에는 출발·도착 영역을 모두 예약한다. 근접·원거리 사거리는 가장 가까운 점유 칸 중심 사이 거리에서 기존 0.7 지름을 뺀 값이며, 투사체 출발·도착 외곽은 같은 지름을 유지한 둥근 사각형이다. 탑승 확장 시 현재 위치를 포함하는 인접 기준점 네 개를 확인한다. 출발·도착 영역을 확보할 수 없으면 저장 전 `NotReady`로 거절하며 다른 유닛을 밀거나 축소하지 않는다. 일반 적·용병은 1×1이고, 아레나 양쪽 플레이어는 각자의 탑승 상태를 적용한다. 서버와 Unity 재생은 [공유 아레나 검증 자료](../cloudflare-event-server/test/fixtures/arenaReplay.json)의 대형 근접·원거리·용병 사례를 함께 소비한다.

`MergeMount`는 용병과 동일하게 서버 경제 명령으로 재료 1~5개의 경험치를 대상에게 이전한다. 서버 `mounts` 원장에서 소유·중복·자기 자신·최대 레벨을 검사하고, `017_Mount_Upgrades`로 계산한 성장·재료 삭제·영수증을 원자 저장한다. 대상의 ID·등급·외형은 유지하며 재화를 쓰지 않는다. 잠금·장착 재료는 클라이언트 선택과 제출 시 보호한다. 서버 응답의 전체 목록을 로컬 저장한 뒤 능력치를 갱신하며 같은 ID의 잠금·장착은 보존한다. 중복 클릭을 차단하고 실패 시 선택을 유지하며, 불확실한 응답·로컬 저장 실패는 같은 작업 ID로 복구한다. 서버 미연결 시 로컬 강화로 대체하지 않는다. 기존 보유 데이터의 최초 서버 원장 복원은 [클라우드 계약](CloudBackend.md)을 따른다.

Total feeding XP is the current source row's CumulativeXP plus stored Experience, including the row-zero base (Common 100, Rare 300, Epic 900, Legendary 2700, Ultimate 8100, Mythic 24300). The next level consumes the following source row's Experience: a Common display level 1 needs 103 XP to reach level 2. `MountRules.AddExperience` returns a copy and supports multiple gains. Level 100 retains excess XP for future feeding, but cannot be a merge target. Negative XP and arithmetic overflow are rejected; no player command accepts arbitrary XP. CumulativeXP is validated against source thresholds.

`GameSession.SelectMountMaterials(expectedRevision, targetId, rarities)` is a read-only selection/preview query. It returns a detached, read-only list of IDs, target/revision, total feeding XP and projected level/remainder. Exact requested rarities are selected in full, excluding the target, equipped mount and locked sources. Results follow source rarity-descending then level-descending ordering, retaining collection order for ties. Empty rarity choices or no eligible sources return a successful empty selection. Selection does not spend, merge, save, publish events or advance revision, and does not stop at the target's level cap. Capped targets, locked auto-selection, unknown targets/rarities, stale revisions and XP overflow return explicit errors. 실제 강화는 선택 결과에서 최대 5개를 골라 `ExecuteAsync(MergeMount)`로 제출하며, 제출 시 revision·보호 상태와 서버 보유 원장을 다시 확인한다.

Auto-selection unlocks when owned mount count reaches `AutoSelectUnlockThreshold` (40), including equipped/locked mounts in that count. The flag persists as optional `gr.ma` and stays true after feeding reduces the count. Successful summons unlock it in the same transaction. Session loading upgrades eligible old collections during the existing resume save; old collections below the threshold remain locked unless the flag was already saved. Historical holdings cannot be recovered from a smaller legacy collection. See [native selection evidence](research/forge-master/MountGrowth.md#automatic-material-selection).

탈것은 90스테이지 클리어 후 `HighestStage >= 91`에서 해금한다. 성장 순서는 용병 31 → 스킬 51 → 기술 연구 71 → 탈것 91이다. 해금 전 소환권·보유 목록은 보존하며 메뉴 진입·가이드·소환·장착·잠금 변경·강화를 막는다. 소환·강화는 서버에서도 같은 조건을 검사한다.

탈것 소환권은 서버 `ClockWinders` 잔액을 표시하며 소환·패스 보상은 서버 경제 경로를 사용한다. 탈것 목록은 3열 카드에 원형 등급 배경·이름·레벨·장착 표시를 배치한다. 목록 클릭 시 용병과 같은 상세 팝업을 열며 왼쪽 강화, 오른쪽 장착/장착 해제, 흰색 잠금/열린 자물쇠 픽토그램을 사용한다. 소환 정보는 별도 팝업이고 강화는 공용 재료 선택 팝업을 사용한다. 12종의 목록 아이콘과 전투 탑승 외형이 연결되어 있다. 소환은 자동 장착이나 강화를 하지 않는다. `LockMount`/`UnlockMount`는 revision을 확인한 로컬 저장 후 표시하며 같은 상태 요청은 토글하지 않는다. 잠금 재료는 선택·강화에서 제외하고 잠긴 대상을 장착하거나 강화하는 것은 허용한다. 저장 실패 시 이전 상태와 이벤트를 보존하며, 잠금·장착 변경은 기존 비동기 클라우드 백업으로 보존한다.

## Research

`022_Tech_Nodes` is the effect-definition contract: `NodeKey`/`Type` identify a research type, and `StatNodeIndex` identifies each effect within that type. `StatType`, `StatNature`, `Layer`, `Condition`, `TargetKind` and `Qualifiers` describe its meaning. `WeaponBonus` and `SkillDamage` each define two effects; these are not two research purchases or two copies of the level value.

`CsvReader.LoadCatalog` validates this contract before publishing a runtime catalog. It checks definition identities, effect indices, qualifier structure, references from `023`/`024`, and the semantic signatures of the 47 implemented research types (49 effect rows). An incompatible definition fails loading with an `022_Tech_Nodes` error instead of silently using a different formula. Qualifier order and JSON whitespace do not affect comparison. The existing explicit domain consumers still execute the formulas and rounding; `022` is not a generic effect interpreter. Adding or changing an effect requires updating its consumer, import contract and tests together. 능력치 효과 수치는 `023`이 소유하며, 새 연구의 인용 시간은 [성장 흐름 정책](BalanceContract.md#콘텐츠-해금과-성장-흐름)의 배율·상한을 함께 적용한다.

Clan placements and definition-only entries such as guild/mission/league bonuses and player movement remain preserved data. Validation does not enable them. A definition without an implemented consumer cannot be placed in an enabled local research tree.

개인 기술 트리 3종은 `024_Tech_Layout`의 노드 ID·연결·티어를 사용한다. 직접 연결된 선행 항목을 각각 1레벨 이상 완료 수령하면 다음 항목이 해금되며 최대 레벨은 요구하지 않는다. 선행 항목이 여러 개면 모두 충족해야 한다. 효과는 `023_Tech_Values`, 비용·시간은 `025_Tech_Tier_Costs`가 소유한다. 연구 노드의 배경판은 연구 중·완료 미수령일 때 밝은 회보라색과 타이머, 최대 레벨일 때 금색과 ‘최대’, 미해금일 때 짙은 빈 슬롯색과 자물쇠로 구분한다. 기술 연구는 모든 브랜치를 합쳐 한 번에 한 항목만 진행한다. 타이머가 끝나도 완료 수령 전까지 다음 연구를 시작할 수 없으며, 직접 완료를 눌러 레벨 증가와 저장이 성공해야 다음 연구를 허용한다. 기존에 시작된 여러 연구는 삭제하지 않고 각각 완료·취소할 수 있지만 모든 연구가 정리되기 전에는 새 연구를 막는다. 서버 `researches`와 로컬 `growth.researches`는 노드 ID별 종료 시각·실제 지불 물약을 보관한다. 이전 단일 타이머는 저장 로드 때 기존 종료 시각·환급액 그대로 한 항목으로 이관하고 이후에는 새 구조만 저장·전송한다. 기술별 레벨과 진행 연구(대상·종료 시각·실제 지불 물약)는 서버 경제 원장이 소유한다. 로그인·재접속과 명령 응답에서 전체 상태를 받아 로컬 캐시를 덮어쓰며 클라우드 플레이어 백업에는 이 필드를 포함하지 않는다. 연구 시작 조건·시간·비용과 다른 경제 명령의 기술 보너스는 서버 원장의 레벨로 계산한다. 연구 시작은 물약을 한 번 소비하며 타이머는 재접속 후에도 유지한다. 시간이 끝나면 완료 대기로 남고 `FinishTech`를 명시적으로 요청하고 서버가 종료 시각과 대상을 검증하여 레벨 증가·영수증을 원자적으로 저장한 뒤 앱의 로컬 저장도 성공해야 레벨과 효과를 적용한다. 같은 작업 ID의 재요청은 기존 결과를 반환하고 다른 작업 ID의 중복 수령은 거절한다. 세션 진행만으로 자동 수령하지 않는다. Values replace a node's prior level and accumulate across completed tiers of the same node type.

기술 노드를 누르면 중앙 팝업에 아이콘·레벨·다음 효과를 표시한다. 연구 전에는 기술 설명 바로 아래에 소요 시간을 별도 줄로 표시하고 버튼에는 시작 문구와 물약 비용만 넣는다. 진행 중에는 진행률·남은 시간과 건너뛰기·취소를, 자연적으로 시간이 끝난 뒤에는 가득 찬 진행 바와 완료 버튼 하나를 표시한다. 완료 대기 중 트리는 기존 레벨 아래에 완료 문구와 빨간 점을 표시하며 재접속 후에도 수령 전 상태를 보존한다. 트리의 레벨 표시는 연구 중에도 유지하며 남은 시간은 그 아래에 표시한다. `SkipTech`는 남은 초를 `GameplayConfig.TechGemSkipSecondsPerGem`(120초)로 나눠 올림한 젬을 차감하고 같은 트랜잭션에서 기술 레벨을 올려 즉시 수령한다. 요청 도착 시 이미 종료된 연구는 젬 없이 수령한다. 진행 중 1~120초는 1젬, 121~240초는 2젬이며, 완료 대기 상태에서는 스킵 버튼을 표시하지 않는다. 기술 스킵은 이 게임의 2분당 1젬 규칙을 사용하며 주사위의 원본 요율은 바꾸지 않는다. `CancelTech`는 확인 후 시작 시 실제 소비한 물약 전액을 환불하고 레벨 증가 없이 연구를 지운다. 시작·스킵·취소·완료 수령은 서버 경제 트랜잭션과 멱등 영수증을 사용한다. 스킵 성공 후에는 연구가 비워져 다음 연구를 시작할 수 있다. 자연 완료는 완료 버튼으로 수령하기 전까지 다음 연구를 시작할 수 없다. 소비 물약의 원본은 서버 연구 기록이며 로컬 저장 `gr.rc`는 표시 캐시다. 로컬 기술 레벨을 서버 원장으로 가져오는 이관은 하지 않는다. 서버는 자기 연구 기록의 대상·시간·비용으로 차감과 환불을 결정하며 클라이언트의 환불 금액을 받지 않는다. 원본 계산과 취소 동작의 근거는 [포지마스터 2.10.0 ARM64 분석](research/forge-master/evidence/tech-research-skip-cancel-2.10.0.txt)에 보존한다.

Implemented consumers: equipment damage/health by slot; equipment forge level caps; active and passive skill stats; skill summon cost; pet stats; rarity hatch timers; extra egg chance; equipped mount stats, mount summon cost and extra mount chance; forge upgrade cost/speed; sell price; free forge chance; automatic forge batch capacity; offline cap/rates; dungeon hammer/gold/skill/potion bonuses; research cost/speed. AutoForge uses the source additive capacity after integer flooring, alongside the existing local unlock capacity. Existing running timers retain their quoted end time when another modifier changes.

MountDamage and MountHealth multiply only the equipped mount contribution by one plus accumulated research value, before player-wide layers. MountSummonCost charges ceil(base cost * max(0, 1 - accumulated value)). ExtraMountChance rolls once per paid summon before rarity selection; success appends one independent rarity/species roll after all paid results. The bonus advances progress too and cannot trigger another bonus. If the resulting batch exceeds the local capacity, the whole command fails without spending currency or committing progress. These Power nodes and their original prerequisite links are active. Existing saved downstream levels and running timers remain intact; future research starts require the mount prerequisites. See [native summon evidence](research/forge-master/MountGrowth.md#research-and-extra-summons). 길드 연구는 별도 공동 포인트 차트와 서버 상태를 사용하며 아래 길드 연구 범위를 따릅니다. 개인 연구의 `Clan` 자리표시자는 계속 비활성화합니다.

## Persistence and validation

Editor-only `PrepareContentPreview` runs through `GameSession.Execute` with the expected revision and the normal atomic save. It raises highest/current stage to at least the largest stage requirement in `FeatureUnlock`, maximizes forge research and all three summon tracks from their charts, clears their pending progress/timer, and grants missing skills at level 1. Existing skill levels, shards, equipment and currencies are retained. Success exits any dungeon and rebuilds the main battle; stale revisions and failed saves leave progression unchanged. This command is excluded from player builds and has no product UI entry.

Optional `gr` storage extends schema 3 with dungeon levels, eggshells, ManaCrystals, summon progress, eggs, pets, mounts, equipment and research. 누락된 탈것 필드는 빈 보유 목록·미장착·소환 재화 0·소환 레벨 1로 초기화한다. Missing `gr` initializes empty growth state without replacing old inventory, skills or currency. Domain/Application remain independent of Unity and JSON serialization. Canonical CSVs remain byte-identical; only the alias projection adds six skill rows.


## Shop and progress pass

일일 무료 보석 버튼은 광고 아이콘과 현지화된 `무료 / Free`를 표시한다. `ClaimShopGemsWithAdAsync`는 보상형 광고의 보상 획득 결과를 받은 뒤 기존 `ClaimDailyFreeGems` 명령으로 지급한다. 광고 미완료·표시 실패·취소에는 지급하지 않으며, 처리 중 중복 클릭을 막는다. 지급 저장 실패 시 같은 세션의 광고 완료 상태를 유지해 재시도하며, 서버 연결 시 기존 서버 재화 명령·영수증 경로를 사용한다.

The shop unlocks after clearing normal battle 2-1 (`HighestStage >= 12`). The battle HUD's right-side progress-pass entry uses the same gate and disappears during dungeon battles. `ShopProductInfo` owns all local paid products and platform IDs, including five gem packs, the progress pass, starter weapon and four daily-deal price tiers. Original APK product IDs remain preserved in `039_Economy_Deals`. A sixth gem card grants 10 free gems once per UTC day (09:00 Korea time), using the same day boundary as dungeon keys. Claims require the shop unlock and persist the last claimed day with the gem grant; failed saves and duplicate claims grant nothing. Missing `shop.freeGemDay` in existing saves defaults to -1. The local paid price tier follows the reference RPG IAP catalog, while reward quantity is a Forge design value; standalone token packs and egg offers remain deferred. No reference USD price or original platform product ID is presented as a live store price.

Daily deals follow the [APK 2.9.0 native behavior](research/forge-master/evidence/daily-deals-arm64.txt): three different types with distinct supported sizes, sorted by size, selected by the original PCG sequence seeded from UTC year/day-of-year and the current refresh round. Purchased cards disappear; buying all three immediately starts another round, with no daily purchase-round cap. UTC midnight resets the round to zero. Dungeon deals have sizes 1–3; other types have sizes 0–3. Rewards come directly from the DailyDeal rows in `039_Economy_Deals`; `ShopProductInfo.DealSizeId` associates the four local IAP tiers with those sizes. Local IDs are `bundle_package_daily_deal_01` through `_04`. No player-triggered refresh button is exposed.

`shop.dailyDealClaims` defaults to an empty list in older saves and stores committed `UTC-day:round:size` claims atomically with rewards and transaction IDs. Gateways must retain validated purchase-day/round context for deferred delivery; an old-day receipt grants its original offer without consuming today's offer. New purchases reject stale displayed day/round context. Dungeon-key rewards add to the existing key count; the [daily refill](#dungeon-battles) at 00:00 UTC (09:00 KST) raises balances below two to two and preserves higher balances without adding a daily allowance. The existing release-gateway restriction below applies to daily deals too.

`036_Progress_Pass` owns the free/premium reward tracks. The pass opens as a modal over its originating battle or shop screen. Green Free and gold Premium headers remain fixed above the shared reward scroll; tapping a reward card claims it without a separate claim button. Claimable free rewards use a gold highlight and a brief repeating scale pulse; collected free rewards are muted with a green check, and unreached free rewards have the premium-style shade without a padlock. Each locked premium reward card is disabled and shaded with a centered padlock. The purchase action remains in the fixed offer area above the Premium header until Premium is owned. Successful commands report completion and saving to the Console rather than an on-screen status label. Claims use the highest cleared source battle, retain separate track IDs, and allow individual or atomic claim-all collection. Buying Premium unlocks eligible past rewards without automatically claiming them. Difficulty-one milestones unlock after their required Hard-mode battle is cleared; campaign difficulty progression follows [BalanceContract.md](BalanceContract.md#campaign-difficulties). Claim IDs, pass entitlement and transaction-to-product records are saved together with rewards. Missing shop fields in old payloads initialize empty; explicit malformed shop payloads are rejected.

패스 팝업은 보상 스크롤 밖 하단 중앙에 ‘모두 받기’를 고정한다. [GameSession.ClaimAllPassRewardsAsync](../Assets/_Project/Application/ShopPurchases.cs)는 기존 `ClaimAllPassRewards` 경제 명령으로 달성한 무료·구매한 프리미엄 트랙의 미수령 보상을 한 번에 수령한다. 수령할 보상이 없으면 버튼을 비활성화하고, 요청 중에는 일괄·개별 수령을 막는다. 성공한 저장의 신규 수령 기록만 재화별로 합쳐 공통 보상 팝업에 표시하며 실패 시 성공 보상을 표시하지 않는다. 서버 연결 시 기존 경제 API·영수증·중복 지급 방지 경로를 사용한다.

연구 시작 시 종료 시각·지불 비용·소요 시간을 함께 저장한다. 이미 시작한 연구의 종료 시각과 진행률 기준은 유지한다. 이전 저장에 소요 시간이 없으면 남은 시간만 정확히 표시하고 진행 막대는 완료 전까지 비워 둔다.

시대 무기 제안은 고대 진입(31스테이지)의 아르케부스 Lv.1(`MedievalWeaponOffer`), 두 번째 세계대전 기관단총 Lv.50(`IndustrialWeaponOffer`), 세 번째 전술 돌격소총 Lv.99(`InformationWeaponOffer`) 순서다. 무기 시대와 판매 해금은 분리하며 첫 상품의 해금은 `ShopProductInfo.UnlockStage`, 무기 레벨은 `EquipmentLevel`이 소유한다. 후속 상품에는 시대 조건이 없다. 첫 상품의 내부 ID와 `FeatureUnlock.medieval_weapon_offer` 키는 기존 구매 이력 식별을 위해 유지한다. 판매 기간은 순서대로 3,600 / 86,400 / 259,200초, 참고 가격은 USD 1.99 / 5.99 / 9.99 및 KRW 2,800 / 8,400 / 14,000이다. 보석은 순서대로 60 / 180 / 300개를 무기와 같은 구매 정산에서 1회 지급하며 첫 구매 2배 보너스는 적용하지 않는다. 무기 티어는 5 / 7 / 8이며 공격 속도 +10%, 정보시대 무기는 치명타 확률 +5%도 지급한다. 가격 상승에 따라 무기의 시대·레벨·옵션 보상이 증가한다. 플랫폼 ID와 등록 기준 가격은 [인앱 상품 목록](store/google-play/in-app-products.md)을 따른다. 차트 반영은 스토어 등록 완료를 뜻하지 않는다. 저장된 기존 무기와 원본 `StarterOffer0` 자료는 유지한다.

해금 이후 첫 저장에서 현재 제안의 상품별 판매 타이머를 시작하며 `shop.weaponOfferProduct`와 `shop.starterEndsAt`·`shop.starterSeen`으로 저장한다. 기존 저장의 상품 ID 누락은 첫 상품으로 읽는다. 현재 상품을 구매하거나 판매 기간이 만료되면 다음 상품으로 바꾸고 기간·닫음 상태를 초기화한다. 재접속 시에도 같은 전이를 적용하며 새 상품의 판매 기간은 전환 시점부터 시작한다. 마지막 상품은 구매·만료 후 종료한다. 같은 상품은 재시작·화면 이동으로 기간을 갱신하지 않는다. 팝업은 다른 안내가 끝난 뒤 한 번 자동 노출하며 닫으면 구매·만료까지 전투 HUD의 무기·카운트다운 바로가기로 연다. 상품별 한 번만 인벤토리에 지급하고 같은 저장에서 즉시 무기 슬롯에 장착한다. 기존 무기는 획득 대기 목록으로 돌려보내며, 처리한 영수증 재전송은 이후 장착 선택을 덮어쓰지 않는다. 내부 `Inventory`는 장착 장비만 유지하고 미장착 장비는 기존 `Pending` 목록으로 보존한다. 기존 저장·복원·새 지급도 저장 확정 전에 같은 규칙을 적용하므로 숨은 별도 가방에 장비가 남지 않는다. 인벤토리가 가득 차면 새 구매를 막고 미완료 영수증을 보존한다. 검증된 미완료 영수증은 만료·후속 상품 전환 뒤에도 원래 상품의 무기를 지급하며 재전송·두 번째 거래가 중복 지급하지 않는다. 실제 결제 gateway와 sandbox 경계는 아래 계약을 따른다.

Reference price evidence: [Korean App Store](https://apps.apple.com/kr/app/forge-master-idle-rpg/id6746636289) lists First Starter Offer at KRW 2,800; [US App Store](https://apps.apple.com/us/app/forge-master-idle-rpg/id6746636289) lists USD 1.99 (checked 2026-10-05). The APK reference value 2.0 has no explicit currency. See [native offer evidence](research/forge-master/evidence/modern-weapon-offer-arm64.txt) for the automatic-popup flag and initial timer.

상점의 일일 소환 재화 구역은 주사위·스킬·용병·탈것·기술 물약 5종을 해금 상태에 따라 표시한다. 각 행에 광고·소량 보석·대량 보석 구매를 배치하며 가격·수량·UTC 한도와 실패 처리는 [경제 계약](CommerceBalance.md#일일-소환-재화-상점)을 따른다.

`ShopPurchases` accepts a platform `IPurchaseGateway`: the adapter must authenticate/validate single-unit orders before returning `VerifiedPurchase`, use stable platform-scoped transaction IDs, expose fetched localized prices only for available products, and redeliver pending startup/restore orders through `DeliverAsync`. Each paid gem product grants twice its chart amount on its first committed purchase, determined by the existing product transaction history. Existing purchases already consume that product’s bonus; free daily gems and the progress pass are excluded. The shop shows the base amount, an additional equal bonus amount and a first-purchase banner until the purchase commits. Application grants these rewards through a revision-checked command, persists the transaction ID atomically, then confirms the order. Confirmation failures retain the committed grant and expose pending confirmation for retry. A storage failure never confirms; redelivery cannot grant twice. Deferred/cancelled orders grant nothing. The release composition currently has no gateway and cannot buy. Real Apple/Google product registration, receipt validation, restore UI and device sandbox testing are required when that adapter is connected; reference IDs/prices are not production registration.

상점·진행 보상의 수량·가격 비교와 기존 지급 보존은 [경제 계약](CommerceBalance.md)을 따른다.

Editor와 Development Build는 SDK 없는 `SandboxPurchaseGateway`와 `local-save-sandbox-v2`를 사용한다. 서버 연결 상태에서도 차트의 USD 미리보기 가격으로 구매할 수 있으며 실제 결제는 발생하지 않는다. 현재 미출시 서버 전체에서 허용한 테스트 구매는 서버 경제 거래로 보상·거래 ID·패키지 회차·성장 패스 권한을 저장한다. 허용 설정과 인앱 도입 시 전환 조건은 [클라우드 계약](CloudBackend.md#미출시-테스트-구매)을 따른다. 일반 빌드는 `local-save-v2`를 사용하고 테스트 gateway 코드를 포함하지 않으며, 실제 스토어 gateway 연결 전에는 구매할 수 없다.

## Main-screen chat

The main screen shows a two-line chat preview and unread badge only after clearing normal battle 3-10 (`HighestStage >= 41`). The source is the `Chat` segment in [Forge Master feature unlocks](research/forge-master/data/feature-unlocks.csv): cleared `MainBattleId(0, 2, 9)`. [ChatRules](../Assets/_Project/Domain/ChatRules.cs) compares completed progress, so a lost battle does not relock chat. Before unlock, both the row and its network activity are absent.

채팅 상단의 전체·길드 탭으로 대화 대상을 선택한다. 전체채팅은 접속 DO와 무관하게 하나의 전역 스트림을 표시한다. 길드채팅은 소속 길드의 별도 기록을 표시하며 전체채팅과 같은 WebSocket으로 실시간 전송·수신한다. 가입 확인 전과 미가입 상태에서는 길드 탭에 자물쇠를 표시하고 선택을 차단한다. 채팅을 열 때 서버 소속을 확인하고 가입·탈퇴 응답과 길드 접근 거절 때 잠금 상태를 갱신한다. 길드별 접근 검증과 전송 계약은 [채팅 계약](../cloudflare-event-server/docs/chat.md#전체길드-탭)을 따른다. [CloudChatSession](../Assets/_Project/Presentation/Cloud/CloudChatSession.cs)이 인증 WebSocket, 전송 ACK와 최근 100개 캐시를 소유한다. 서버가 대기 시간을 추가하지 않고 전파한 `chat.batch`를 받으면 메시지와 삭제를 적용하고 배치 cursor를 ACK한다. 중복은 다시 표시하지 않고 누락은 HTTP로 복구한다. 최초 접속·재접속은 `chat.ready` 후 HTTP 최신 기록으로 삭제도 재조정한다. 연결 단절 중에는 캐시와 입력 초안을 유지하고 연결 중 상태를 표시하며 발언을 막는다. HTTP 대체 발언·본문 polling은 없으며 이력 조회는 연결 후 최초·재접속·누락·차단 변경 복구에 사용한다. membership과 수신 정책은 기존 게임 세션 확인에 연계하며 채팅 전용 HTTP heartbeat는 없다. 마지막 배치의 ACK 정체는 서버 alarm이 소켓을 닫아 재접속을 유도한다. Close 유실·정책 전달 실패는 기존 게임 권한 응답의 재연결 신호로 복구한다. 재접속은 2~60초 지수 backoff에 jitter를 적용한다. preview는 전체 창을 닫아도 같은 전경 연결을 유지하고, 앱 일시정지·비활성화·계정 변경 시 기존 작업을 취소한다. 서버 한도·복구·정책 유효기간은 [채팅 계약](../cloudflare-event-server/docs/chat.md)이 소유한다.

Sending immediately adds a local pending row and clears the composer before any network response. The next draft remains editable while the send button waits for the current request to finish; acknowledgements and echoes never erase that new draft. Message sends are attempted once, without automatic retransmission or composer restoration. An empty composer never resends previous text. Acknowledgement replaces it with the server sequence and timestamp; failed or uncertain sends discard the local pending row and retained draft. Moderation rejection adds a local System notice. Own-message history includes `requestId`, allowing a received message to reconcile a lost acknowledgement without a duplicate row. Other users never receive that ID. Chat history is not part of the player save. Server deployment is a separate operation; the UI shows connection failure when chat is unavailable.

The chat page reuses the game palette and profile artwork. Rows show a profile, nickname, local `HH:mm` timestamp and wrapping message bubble; the composer and back button stay below the scroll area. Arena and chat opponent inspection reuse the player detail view: a character wearing the opponent equipment, equipped companions in the scene preview, the eight-slot equipment grid, skill icons with levels, and public stats. Companions appear only in the scene preview, without duplicate icons below the equipment. Remote preview rigs are owned by the attached UI element and released on close. Public profiles include forge level and gender; older cached profiles without these fields omit those labels. Other players have a Battle button for a local friendly duel against their server-projected build; it spends no tickets, changes no rating and grants no rewards. Completion or exit returns to chat. Guild names and emblems are absent. Current chat responses do not contain avatar IDs, so other players use the default profile; the local player uses their selected avatar.

### 평가 요청 팝업

보통 난이도 2시대 3전투·4시대 3전투에 최초 도달하여 진행 저장이 성공하면 평가 팝업을 표시한다. 로딩·다른 팝업·전투 전환 중에는 대기하며 로그인 시 소급 표시하지 않는다. 파란색 평가하기 버튼 하나와 닫기 버튼을 제공하고, 평가하기 클릭은 `MarkRatingClicked` 명령으로 `HasClickedRating`을 로컬에 즉시 저장하고 기존 5분 주기 비동기 클라우드 백업에 포함한다. 저장 성공 후 닫고 이후 노출을 막으며, Android에서는 현재 앱 패키지의 Google Play 상세 페이지를 Play 앱으로 연다. Play 앱을 실행할 수 없으면 같은 상세 페이지의 웹 주소를 연다. 저장 실패 시 팝업을 유지하고 마켓으로 이동하지 않는다. 닫기 버튼은 기록하거나 마켓을 열지 않는다. 클라우드 백업·복원에도 클릭 기록이 포함된다. iOS 마켓 이동·의견 전송·연령 조건은 미구현이며 이 기록은 실제 평가 완료가 아닌 버튼 클릭을 의미한다. [원본 노출 조건과 적용 차이](research/forge-master/RatingPrompt.md)를 참조한다.

## 개발 치트

Editor와 Development Build는 설정 팝업 테두리 바깥 아래에 개발 치트 버튼을 제공한다. 설정 목록과 함께 스크롤되지 않으며 설정 탭에서만 표시한다. 일반 빌드에서는 버튼을 숨기고 연결 코드·명령·전투 가드를 컴파일에서 제외한다. 무적은 아군 전체의 피해를 차단하고 적 즉사는 적에게 피해가 명중하면 처치한다. 두 기능은 일반 전투·던전에만 적용하며 아레나는 제외한다. 전투 배속은 제공하지 않는다. 전투 토글과 보상형 광고 생략은 세션에만 남고 재시작하면 해제된다. 광고 생략도 기존 광고 완료 이후의 보상·저장 경로를 사용한다.

진행·재화·장비 변경은 예상 revision을 갖는 `GameCommand`로 저장한다. 저장 실패 시 이전 상태를 유지한다. 스테이지 이동은 선택 스테이지까지, 클리어 처리는 그 다음까지 해금하며 별도 클리어 보상은 주지 않는다. 시대 세트는 원시 시대·우주 시대 등 10개 장비 시대 중 하나를 드롭다운으로 선택하고, 선택 시대의 8부위 Lv.1 장비를 한 번에 지급한다. 스테이지·주사위 레벨·현재 장착은 변경하지 않는다. 기존 인벤토리와 서버 소유 성장·재화는 유지하며 용량 부족 시 전체 적용을 거절한다. 재화 초기화는 확인 후 적용한다.

주사위 레벨은 1부터 현행 최대 레벨까지 드롭다운으로 선택한다. 레벨 설정은 진행 업그레이드와 분할 납부를 지우며, 즉시 완료는 실제 업그레이드 진행 중에만 한 레벨 올린다. 지정 장비는 시대·부위·외형·레벨(1~149)을 선택하고, 시대 세트는 각 부위의 기본 외형을 사용한다. 장비는 현행 카탈로그와 시대별 옵션 개수를 따른다. 골드·주사위는 로컬, 나머지 주요 재화와 던전 열쇠·단계는 [서버 개발 치트](CloudBackend.md#개발-치트)의 영수증 경로를 사용한다. UI 단계 1~400은 서버 인덱스 0~399로 전달하며 최종 클리어 기록은 해제한다. 실행 중에는 치트 입력을 잠가 중복 제출을 막는다.

## 비강제 손가락 안내

첫 강화 안내는 스킬·용병·탈것별로 따로 기록한다. 해금과 강화 재료 조건을 충족하면 메뉴·대상 선택을 안내하며, 스킬은 강화 버튼이 있는 상세 팝업을 열 때, 용병·탈것은 업그레이드 재료 선택 팝업을 열 때 완료한다. 팝업 안의 재료 선택·강화 실행은 안내하지 않는다. 잠금·장착 중인 용병과 탈것은 재료로 계산하지 않는다. 완료 이력 저장 실패에는 완료하지 않고, 성공 후에는 재료가 늘어도 다시 안내하지 않는다.

기술 연구 안내는 기능 해금 후 기술 포션으로 연구 가능한 항목이 있을 때 시작한다. 포션 획득 경로와 관계없이 성장 메뉴 → 기술 탭 → 연구 분야 → 연구 항목 → 연구 시작을 안내한다. 던전 안에서는 숨기고 복귀 후 실행 조건에 맞춰 표시한다. 첫 연구 시작의 저장 성공으로 종료하며 연구 대기·유료 즉시 완료는 안내하지 않는다. 이미 연구 중이거나 연구 레벨이 있는 플레이어에게는 다시 안내하지 않으며, 첫 시작 후 취소해도 재시작하지 않는다.

`GuideRules`가 용병의 실행 가능한 단계를 판단하고 `GameHud.Guides`가 현재 화면의 실제 버튼을 찾아 안내한다. RPG 프로젝트의 단계 판단·완료 기록·표시 분리 구조를 참고했으며, 입력 차단·강제 화면 이동·전투 정지·배경 가림은 넣지 않는다.

- 안내 트리거를 달성하고 대상 버튼이 표시·활성화되면 즉시 표시한다. 현재 안내가 실행 가능하면 새 해금·재화 획득으로 교체하지 않는다. 재화·재료 부족이나 대상 장비 부재 등으로 실행 불가능해지면 세션 내 대기 목록에 보류하고 실행 가능한 다른 안내를 시작한다. 현재 안내 완료 후 보류 순서대로 조건을 재확인하여 실행 가능한 기존 안내를 우선 재개하고, 없으면 새 안내를 기존 우선순위로 선택한다. 보류한 안내가 다시 가능해져도 진행 중인 안내를 가로채지 않는다. 단순 메뉴 이동·팝업 가림·스크롤 밖 이동은 보류 사유가 아니며 손만 숨긴다. 로딩·통신·전투 중에는 안내 선택을 멈춘다. 완료 이력만 저장하며 재접속 시 활성·대기 순서는 현재 조건으로 다시 계산한다. 입력 차단·재표시 대기 시간·노출 횟수 제한은 없다.
- 일반 스테이지의 승리·패배 전환은 손가락을 숨기거나 움직임을 재시작하지 않는다. 통신·결과 연출 또는 대상 버튼이 가려져 잠시 숨겨지면, 표시 가능한 상태로 돌아왔을 때 즉시 이어서 안내한다. 메뉴 열기·대상 선택·장착 확인은 현재 진행 상태에 따라 다음 행동으로 전환하며 별도 주기 대기 없이 손가락 갱신 시점에 대상을 확인한다.
- 손가락은 크기를 바꾸지 않고 상하로 움직인다. 같은 안내를 유지하는 동안 입력만으로 움직임을 재시작하지 않으며, 안내 대상이 바뀌거나 숨김에서 복귀하면 시작 위치부터 움직인다.
- 용병은 기능 해금 및 소환 재화 확보 → 소환 → 훈련생 선택 → 첫 훈련 시작까지 안내한다. 기존 훈련생이 있으면 소환을 건너뛴다. 훈련 시작 저장 성공으로 안내를 완료하며 훈련 대기·완료 수령·전투 배치는 안내하지 않는다. 이미 훈련 중이거나 보유 용병이 있으면 안내를 생략하며, 훈련 대기 중 다른 안내를 막지 않는다. 완료 이력 비트 16은 유지하고 식별자는 `PetTrainingStarted`로 사용한다.
- 스킬·탈것은 실행 가능한 소환 또는 보유 대상 장착을 안내하고 첫 장착 저장으로 완료한다. 장비 첫 획득·첫 장착(빈 부위 장착 또는 전투력이 증가하는 교체)·첫 판매, 첫 계급의 보상 수령과 승급, 자동 소환, 시간 보상, 열려 있고 입장권이 있는 던전, 도전 가능한 아레나도 현재 화면과 실행 조건에 맞춰 안내한다. 계급은 퀘스트 하나라도 현재 보상을 수령할 수 있으면 메인 승급 메뉴 버튼을 안내한다. 다른 퀘스트가 미완료여서 실제 승급 버튼이 비활성인 상태도 포함한다. 화면 안에서는 현재 수령 가능한 보상을 레벨 → 주사위 → 스테이지 순서로 안내한다. 수령 가능한 보상이 없고 다른 조건이 남아 있으면 안내를 보류하며, 세 보상을 모두 수령한 뒤에만 실제 승급 버튼을 안내한다. 보상 하나를 받아도 승급 안내 흐름을 종료하지 않는다. 첫 승급이 저장되면 계급 안내를 완전히 종료하며 다음 계급에서 수령 가능한 보상이 생겨도 다시 표시하지 않는다.
- 용병·스킬 카드의 손끝은 스크롤 이동 반영 후 화면에 보이는 카드 영역의 중앙을 따라 움직인다. 보이는 높이가 애니메이션 이동 폭보다 작거나 카드가 화면 밖이면 숨기고, 다시 충분히 보이면 같은 대상을 안내한다.
- 장비 비교창이 열리면 그 창에서 실행 가능한 첫 장착·판매 안내를 우선하고, 가려진 기존 안내는 세션 대기 목록에 보존해 비교가 끝난 뒤 재개한다. 장비가 도착했다는 이유만으로 메인 화면의 실행 가능한 안내를 바꾸지는 않는다.
- 팝업 뒤·스크롤 밖·비활성 버튼은 가리키지 않는다. 로딩, 결과 연출, 던전·아레나 전투, 통신 중에는 숨긴다. 메뉴를 닫거나 다른 화면으로 이동해도 진행을 강요하지 않는다.
- 대장간은 첫 업그레이드 해금 조건과 납부 재화를 충족하면 진입·납부·시작을 안내한다. 현재 첫 업그레이드는 일시불이므로 시작 버튼을 안내하고, 시작 후 무료 즉시 완료 버튼까지 이어서 안내한다. 유료 즉시 완료는 안내하지 않는다. 무료 즉시 완료 또는 시간 만료에 따른 자동 완료로 대장간 레벨이 2가 되면 종료하며 이후 업그레이드는 안내하지 않는다.
- 장비 안내는 첫 장착과 첫 판매를 각각 한 번 안내하며 순서는 고정하지 않는다. 빈 슬롯 장착 또는 전투력이 증가하는 교체는 장착 버튼을, 기존 장비보다 전투력이 증가하지 않는 장비는 판매 버튼을 가리킨다. 각 행동의 저장 성공으로 해당 안내만 완료하고, 두 행동은 같은 장비 안내 흐름으로 관리하되, 남은 행동에 맞는 대기 장비가 없으면 보류하여 다른 안내를 허용한다. 비교창을 닫으면 대기 장비를 여는 것부터 이어가며, 완료된 장착·판매 안내는 반복하지 않는다.
- 완료 이력은 `PlayerData.Guides` / 저장 필드 `guides`이며 성공한 Application 명령의 저장과 함께 확정된다. 저장 실패에는 완료하지 않는다. 기존 저장에 필드가 없으면 미완료이며, 현재 장착·진행 상태도 함께 확인하여 이미 수행한 행동을 불필요하게 안내하지 않는다.
- 스킬 소환으로 빈 슬롯에 자동 장착되면 첫 장착 완료를 기록하고, 용병은 훈련 시작으로 완료를 기록한다. 로컬 명령과 서버 영수증 모두 해당 동작과 완료 이력을 같은 저장에 반영한다. 아레나는 해금 후 처음 열기 전에도 진입을 안내하며, 화면 안의 도전은 서버가 도전 가능하다고 응답한 경우에만 안내한다.
- 길드는 기능 해금 후 미가입 상태이며 화면 열기 이력이 없을 때 `btn-guild`를 안내한다. 길드 화면을 열면 `GuildOpened`를 저장하고 종료하며 가입·신청은 요구하지 않는다. 가입 중에는 안내하지 않고, 이미 화면을 열었다면 탈퇴·재접속 후에도 반복하지 않는다. 저장 실패 시 완료 이력은 확정하지 않는다.
